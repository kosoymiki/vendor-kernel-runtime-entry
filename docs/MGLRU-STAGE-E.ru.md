# MGLRU Stage E — поколенческая политика (`ktramp` 1.1.0)

Stage E превращает трамплин из счётчика в MGLRU-подобное решение: защищать
молодой рабочий набор, но позволять сканировать и вытеснять холодные страницы
(«evict oldest first»). Это runtime-политика на границе `get_scan_count`.
Пересборка vmscan не нужна: `kpatch` заменяет тело функции, `ktramp` делает
трамплин целой функции с вызовом оригинала, а kprobes хукают reclaim path.
Вместе это слой совместимости (CFI-bridge, MODVERSIONS, vermagic, reloc
init/exit, SMP-safe патчинг), который делает кастомную reclaim-политику
возможной без изменения образа ядра.

## Механизм

- kprobe `mark_page_accessed`: каждый доступ сохраняет `page -> generation` в
  folio-таблице и увеличивает счётчик доступов lruvec.
- kprobe `workingset_eviction`: если `cur_gen - page_gen <= 1`, страница
  доступна в текущем поколении и считается **young**, иначе **cold**.
- kprobe `workingset_refault`: распаковывает timestamp из shadow ядра
  (`shadow >> 19`) и считает refault distance относительно
  `lruvec->nonresident_age` (offset 96).
- Политика в трамплине `get_scan_count`, по порядку:
  1. refault distance `d != 0`: `d <= 32` обнуляет file-сканы, иначе делит их
     пополам;
  2. `young/(young+cold) > 60%`: вдвое уменьшить file-сканы (защита рабочего
     набора);
  3. `young/(young+cold) < 20%`: оставить полный скан (доминируют холодные);
  4. иначе — чётность поколения per-memcg;
  5. `can_swap` последним: только обнуляет anon-счётчики (ядро уже делает это
     без swap, `mm/vmscan.c:2522`).
- Инъекции для недостижимых входов: `echo t5` форсирует `d=5`; `echo y80`
  форсирует young/cold 80/20. Обе debug-only и видны в readback (`fd=`,
  `fyc=`).

## Наблюдения в QEMU (stock `Image`, 512 MiB, без swap)

`tests/qemu_ktramp_gate.sh` (модуль sha `85d01060…`):

| режим | счётчики | ветка | подавление |
|---|---|---|---|
| холодный ext4-кэш | `yc=0/398`, `nr_calls=108` | 7 (полный скан) | `delta20=2 / pre20=610` |
| форс young `y80` | `fyc=80/20` | **6** | `delta20=376 / pre20=736` = **51.1%** |
| форс distance `t5` | `fd=5` | **1** | `delta20=8703 / pre20=8703` = **100%** |
| реальный refault (`MADV_PAGEOUT` 128 KiB) | `refaults>0` | 2 | `tdist=847` |
| restore + unload | — | — | `patched 1→0`, `rmmod_rc=0`, `proc_gone`, `module_gone` |

Интерпретация: обе реальные нагрузки вытесняют только холодные страницы,
поэтому полный скан — правильное поведение MGLRU; ветка защиты молодого
набора достигается детерминированно через `y80` и подавляет 51.1% запрошенных
file-сканов.

## Тесты

- `modules/ktramp/tests/test_policy.c`: 29/29 PASS (ветки 1–7, порядок
  no-swap, распаковка shadow, маска distance, folio head, таблица вытеснения).
- QEMU-гейт выше: cold, `y80`, `t5`, refault, restore, unload.

## Ограничения

- Поколение растёт по кванту сканов (64 скана), а не по точным часам
  `min_seq/max_seq` MGLRU.
- Для реального вытеснения young нужен рабочий набор больше свободной памяти;
  гейт 512 MiB вытесняет только холодные страницы, отсюда помеченная инъекция.
- Политика меняет только `nr[]`; структуры ядра не модифицируются.
